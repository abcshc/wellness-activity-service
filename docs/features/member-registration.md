# 회원가입

> 상태: 구현 완료

## 목적

이름, 닉네임, 이메일, 비밀번호를 입력받아 회원을 생성합니다. 이후 인증과 건강활동 데이터의 소유자를 식별하는 기준을 제공합니다.

## 구현 완료 범위

- 이메일 중복 가입 방지
- 비밀번호 단방향 해시 저장
- `POST /api/v1/members` 회원가입 API
- 요청 필드 검증과 공통 오류 응답

## 데이터 항목

| 항목 | 설명 |
| --- | --- |
| 이름 | 회원의 이름 |
| 닉네임 | 서비스에서 사용할 닉네임 |
| 이메일 | 로그인 식별자 및 중복 가입 검증 기준 |
| 비밀번호 | 원문을 저장하지 않고 단방향 해시로 저장 |

## 설계 원칙

- 이메일은 정규화한 뒤 유니크 제약조건으로 중복을 방지합니다.
- 비밀번호 원문과 비밀번호 해시는 응답·로그에 포함하지 않습니다.
- 회원의 직접 식별 정보와 건강활동 데이터는 논리적으로 분리합니다.
- 서비스에서 이메일 중복을 먼저 확인하고, 동시에 발생한 요청으로 인한 중복 저장은 데이터베이스의 이메일 유니크 제약조건으로 차단합니다.

## API

### 회원가입

`POST /api/v1/members`

```json
{
  "name": "홍길동",
  "nickname": "길동이",
  "email": "gildong@example.com",
  "password": "password"
}
```

성공하면 `201 Created`와 비밀번호를 제외한 회원 정보를 반환합니다.

```json
{
  "name": "홍길동",
  "nickname": "길동이",
  "email": "gildong@example.com"
}
```

### 입력 검증

| 필드 | 규칙 |
| --- | --- |
| `name` | 필수, 최대 100자 |
| `nickname` | 필수, 최대 30자 |
| `email` | 필수, 이메일 형식, 최대 254자. 앞뒤 공백은 허용하지 않음 |
| `password` | 필수, UTF-8 기준 최대 72바이트 |

입력 검증 실패는 `400 Bad Request`와 `INVALID_REQUEST` 오류 코드로 응답합니다. 이미 가입된 이메일은 `409 Conflict`와 `MEMBER_EMAIL_ALREADY_EXISTS` 오류 코드로 응답합니다. 오류 본문 형식은 [공통 오류 처리](../common/error-handling.md)를 따릅니다.

## 비밀번호 해시 방식

> 상태: 구현 완료

- `spring-security-crypto`의 `BCryptPasswordEncoder`를 사용합니다.
- 비용 계수는 BCrypt 기본값인 10을 사용합니다.
- 직접 생성한 BCrypt 해시는 항상 60자이므로 `password_hash`는 `VARCHAR(60)`으로 저장합니다.
- 신규 비밀번호는 UTF-8 기준 72바이트를 초과하면 입력값 오류로 처리합니다.
- 전체 Spring Security 인증 설정은 로그인 기능을 구현할 때 별도로 추가합니다.

## 검증 완료 범위

- BCrypt 해시가 평문과 다르고 `matches` 검증에 성공하는지 확인합니다.
- 생성된 BCrypt 해시가 60자인지 확인합니다.
- UTF-8 기준 72바이트 비밀번호는 해시할 수 있고, 73바이트 비밀번호는 거부되는지 확인합니다.
- Spring 컨텍스트에서 회원가입 서비스와 BCrypt 해시 구현체가 연결되는지 확인합니다.
- MockMvc로 성공, 필수값·형식 오류, 비밀번호 바이트 제한, 이메일 중복, 비밀번호 비노출을 확인합니다.
